## Security and architecture hardening in this release
Each item was reproduced first, then fixed, then given a regression test.
1. **PDF decompression bomb:** a 142 KB upload inflated ~150 MB (317 MB peak RSS). Streams are now inflated with ceilings (20 MB each, 40 MB per file); the upload is refused with 422 and nothing is stored.
2. **Extraction resource use:** a 10 MB document produced 160,000 roles (~700 MB) and a draft the API could not edit (limit 50). Extracted text above 2,000,000 characters is refused; extraction keeps 50 roles and 60 skills per role, with a note.
3. **Request bodies were fully read before being rejected** (a 60 MB body took the full parse). A middleware now answers 413 from `Content-Length` before reading, and 411 when the length is missing (no chunked bypass).
4. **Key management fail-closed branch was untested:** now tested (production mode without keys refuses; a bad key is never echoed; the document key cannot open finance data).
5. **Database integrity:** 30 `CHECK` constraints (statuses, roles, bases, units, currencies, scopes, month/duration ranges), enforced and tested at the database on SQLite and PostgreSQL.
6. **Authorization matrix:** a test enumerates every `/api/opportunities/{oid}/…` route (a new route is included automatically) and proves six different non-members get 403/404 with no leakage. No defect found; the test now guards the property.
7. Earlier in this milestone (also fixed): scenario results and cost columns were stored unencrypted (now Fernet with the finance key); certificate eligibility now reads CERTIFIED evidence; duplicate uploads/roles are idempotent/merged; tolerant local-model parsing with source-quote verification.

## Not production-grade — read this
* **Local encryption is not production-grade.** In local/test mode the key is derived from a constant published in this repository, so it is obfuscation. Production requires `HOI_DOC_KEY` and `HOI_FINANCE_KEY` from a secret manager; there is no key rotation or re-encryption tooling.
* Audit integrity is tamper-evident, not tamper-proof (no external anchor for the per-opportunity chain).
* No maker-checker rule: the person who creates a scenario can give their own lane's approval.
* Each internal match stores ordinary Hermes staffing requests (needed for the audited name reveal); they show as open requests on the Overview and in Requests.
* Malware scanning, OCR, HRIS/payroll, capacity, ATS/vendor feeds, Entra ID role mapping, Word/Excel/PDF pack, fairness review and extraction precision/recall are all still pending (see HOI_SECURITY_AND_DATA_BOUNDARIES.md).
* Not run on PostgreSQL: 6 HOI tests that read the SQLite file directly and the full 537-test suite.
* The original demo instance (port 8001) was left running throughout; its static frontend now serves the rebuilt bundle while its backend is the older process.
